# AGENTS.md

Instructions for AI coding agents working on this repository. Read this file before making changes.

**Note for agents:** this file is read by a **non-deterministic** model, so the critical rules are **bolded** and **repeated at the end on purpose**. Repetition is not an accident — do not remove it.

## Project

The Grain — a small social network (registration, login, short text posts, a public feed).
Monorepo: `server/` (Elysia API on Bun) + `client/` (Vue 3 SPA on Vite) + PostgreSQL 16 in Docker.

## Architecture at a glance

```
Client — Vue 3 SPA (:5173)  ──HTTP/JSON──►  API — Elysia on Bun (:3000)  ──SQL──►  PostgreSQL 16 (:5433, Docker)
```

- The client is a **single-page application**; the API is **stateless** (no sessions — a JWT carries the identity).
- Database access goes through **Drizzle ORM**; the schema is code (`server/db/schema.ts`).
- CORS is fully open (`cors()` with defaults) — this is a local development project.
- The API port `3000` is **hardcoded** in `server/index.ts` (`listen(3000)`); there is **no `PORT` environment variable**.
- The client API URL is **hardcoded** in `client/src/api/client.ts` (`API_URL = "http://localhost:3000"`) — if you change the API port, change both places.

## Data model

```
users                                posts
─────                                ─────
id             uuid, PK              id          uuid, PK
email          varchar(255), UQ, NOT NULL        user_id     uuid, NOT NULL,
username       varchar(50), UQ, NOT NULL         │           FK → users.id ON DELETE CASCADE
password_hash  text, NOT NULL        content     text, NOT NULL
created_at     timestamptz,           created_at  timestamptz,
               DEFAULT now(), NOT NULL            DEFAULT now(), NOT NULL
```

- Primary keys are UUIDs generated by the database (`defaultRandom()`) — never send an `id` on insert.
- `email` and `username` are unique — duplicates are rejected with `409` (checked in code **and** enforced by the database; the unique violation code `23505` is handled as a race condition).
- Passwords are stored **only** as argon2id hashes (`Bun.password.hash`, default algorithm).
- `posts.content` is `text` in the database; the 500-character limit exists **only** in the API validation, so inserting via SQL directly can bypass it.
- Drizzle type helpers are exported from `server/db/schema.ts`: `User`, `NewUser`, `Post`, `NewPost`.

## Request lifecycle

Example: an authenticated user publishes a post.

1. **Client** — the form submits in `FeedPage.vue`; `api.createPost(content)` (`client/src/api/client.ts`) sends `POST /api/posts` with a JSON body and `Authorization: Bearer <token>` (token read from `localStorage`).
2. **CORS + routing** — Elysia applies `cors()`, then matches the route in `server/routes/posts.ts`.
3. **Validation** — the `body` schema (`t.Object`) validates `content` (1–500 characters); a failure becomes `400` via the central `onError` handler.
4. **Auth guard** — the `isAuth` macro (`server/middleware/requireAuth.ts`) checks the `Authorization` header and verifies the JWT; failure → `401`. On success it puts `userId` into the handler context.
5. **Handler** — the handler inserts the row via Drizzle (`db.insert(posts)...returning()`), loads the author `{ id, username }` and sets `set.status = 201`.
6. **Database** — PostgreSQL stores the row; `posts.user_id` references `users.id` with `ON DELETE CASCADE`.
7. **Response** — the client receives the created post, `posts.value.unshift(created)` updates the feed state and Vue re-renders the list (no page reload).

Unexpected errors anywhere in the chain are logged by the central `onError` handler (`console.error`) and returned as `{ error: "Server error" }` with status `500` — internals are **never** exposed to the client.

## Authentication and security

- The JWT plugin (`@elysiajs/jwt`) is registered under the name `jwt` in `server/middleware/auth.ts` with the secret from `JWT_SECRET`. **The module throws at import time if `JWT_SECRET` is missing** — the server refuses to start rather than run without a secret.
- Tokens are signed at login with payload `{ userId, exp: "7d" }` — **valid for 7 days**.
- Guard messages are exact and tested: `401 { error: "Token is missing" }` when the header is absent or not `Bearer …`, `401 { error: "Invalid or expired token" }` when the signature/expiry fails or `userId` is not a string.
- `login` returns the **same** `401 Invalid email or password` for an unknown email and a wrong password (it does not reveal whether an account exists).
- Password verification uses `Bun.password.verify`. Hashes and `password_hash` are **never** returned by any endpoint.
- Client session: `localStorage` keys are `token`, `user` (JSON) and `locale`; `api/client.ts` attaches the bearer token to every request automatically.
- A `401` from the API surfaces as a thrown `Error` on the page; there is **no automatic logout/redirect** — pages just display the message.
- **Out of scope on purpose (do not add without an explicit request):** refresh tokens, cookies, rate limiting, email verification, token revocation, role-based access, HTTPS setup.

## Client architecture (what agents need)

- **API layer** (`client/src/api/client.ts`): a single `request()` wrapper around `fetch`; adds `Content-Type` and the bearer token; parses JSON with a `.catch(() => ({}))` fallback; on `!response.ok` throws `new Error(data.error + (data.message ? ": " + data.message : ""))`, otherwise returns the parsed data. Exposed methods: `register`, `login`, `me`, `getPosts`, `createPost`. Types `User`, `Post` are exported from here.
- **Session state** (`client/src/composables/useAuth.ts`): module-level `ref`s (`user`, `token`), `isAuthenticated` computed (`token !== null`), `login` (calls API, saves session), `logout` (clears refs and `localStorage`).
- **Routing** (`client/src/router/index.ts`): `createWebHistory`, routes `/feed`, `/login`, `/register`; `/` redirects to `/feed`. **There are no route guards** — the feed is public by design; only API operations are protected.
- **Pages**:
  - `RegisterPage` — calls `api.register`; on success shows a message and redirects to `/login` after 1.2 s (**registration does not log you in**);
  - `LoginPage` — calls `login()` from `useAuth`, then redirects to `/feed`;
  - `FeedPage` — loads the feed on mount; groups posts by calendar day with `Today`/`Yesterday` labels via `t()` and `d()`; shows the post form only when authenticated; anonymous users see a login hint; shows a counter via `t("feed.posts", n)`.
- **Components**: `PostCard` — props `{ post: Post }`; falls back to `t("post.unknownAuthor")` when `author` is `null`; highlights the current user's own posts (`post-author--own`).
- **App shell** (`App.vue`): logo link, language switch (EN | RU buttons + moving thumb), username + logout button when authenticated, `Log in` link otherwise.
- **Styling**: single global stylesheet `client/src/style.css` (CSS variables, dark theme, wheat accent); no CSS framework, no scoped component styles.

## Error contract

Every error response has a single `error` field; validation errors add `field` and `message` (`field` is the **first** failing path only, with the leading `/` stripped). Exact messages:

| Status | Source                     | Messages / notes                                                                                                      |
| ------ | -------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `400`  | `onError VALIDATION`       | `Invalid data` + `field` + `message` (first issue only)                                                               |
| `400`  | `onError PARSE`            | `Malformed JSON in request body`                                                                                      |
| `401`  | `isAuth` guard             | `Token is missing` / `Invalid or expired token`                                                                       |
| `401`  | `login`                    | `Invalid email or password` (same message for unknown email and wrong password)                                       |
| `404`  | `onError NOT_FOUND` / `me` | `Route not found` / `User not found` (valid token, deleted user)                                                      |
| `409`  | `register`                 | `email is already taken`, `username is already taken`; race condition (`23505`): `Email or username is already taken` |
| `500`  | handlers / `onError`       | `Server error`, `Failed to create user`, `Failed to create post` (details only in the server console)                 |

Client behavior: the wrapper throws an `Error` with the API message (plus `: message` when present); pages display `error.message` with an i18n fallback string.

## Database workflow

1. Edit `server/db/schema.ts` (Drizzle table definitions).
2. `bunx drizzle-kit generate` — creates `drizzle/000N_name.sql` and updates `drizzle/meta/`.
3. **Review the generated SQL** before applying it.
4. `bunx drizzle-kit migrate` — applies pending migrations (the database must be up: `docker compose up -d`).
5. **Never edit a migration that has been applied** and never hand-edit `drizzle/meta/` — change the schema and generate a new migration.
6. `drizzle.config.ts` runs with `verbose: true, strict: true`; migrations in `drizzle/` are committed together with the schema change.
7. There is no `drizzle-kit push` in this project — schema changes always go through generated migrations.

## Common tasks (playbooks)

### Add an API endpoint

1. Add the route to the matching router in `server/routes/`, following the existing Elysia chain style.
2. Validate the input with `t.Object` — **never trust the body**.
3. For protected routes pass `{ isAuth: true }` and take `userId` **from the guard (context), never from the body**.
4. Set statuses explicitly (`set.status = 201`); for expected failures return `{ error: "..." }` with a 4xx status instead of throwing.
5. If you create a new router, wire it in `server/index.ts` (`.use(newRoutes)`).
6. Update `docs/API.md` and the endpoint table in `README.md` if the contract changed.
7. Verify: start the server, call the endpoint with `curl`, then run `bun run lint` and `bun run typecheck`.

### Add a UI string

1. Add the key to **both** `client/src/i18n/en.json` and `ru.json` (the key sets must stay identical).
2. Use `t("key")` in the component — **never hardcode UI text**.
3. Run `bun run ci:format`.

### Add a page

1. Create `client/src/pages/XxxPage.vue` with `<script setup lang="ts">`.
2. Register the route in `client/src/router/index.ts`.
3. Put all text through `t()` (add the keys to both dictionaries).

### Add a new locale

1. Create `client/src/i18n/<code>.json` and translate **every** key (the sets must match `en.json` exactly);
2. Register it in `client/src/i18n/index.ts`: import the JSON, add it to `messages`, extend the `Locale` type and the `initial` check;
3. Add `datetimeFormats` for the locale (dates and time — see the EN/RU examples: 12-hour vs 24-hour);
4. If the language has complex plurals, add a rule to `pluralRules` (model it on `pluralRuleRu`);
5. Add the language button to the switch in `App.vue` (and the thumb positioning CSS in `style.css`);
6. Verify: switch the language, reload (persistence), check dates/times and plural forms.

### Add a dependency

1. Decide the owner: API dependencies go to the root `package.json`; client dependencies go to `client/package.json` (`cd client && bun add ...`).
2. Integrate the package with the existing style (no alternative HTTP clients, state libraries, etc. without discussing it).
3. Run the verification checklist.

### Change the database schema

See "Database workflow" above.

### Change the API port

Two places must change together: `listen(3000)` in `server/index.ts` and `API_URL` in `client/src/api/client.ts` (plus any local tooling/config you use — there is no shared constant).

### Rotate `JWT_SECRET`

Change it in `.env` and restart the API. **Every existing token becomes invalid** — all users are logged out and get `401` until they log in again.

### Release a change

See "Git and PR workflow" below.

## Code style snippets

Route skeleton (Elysia):

```ts
import { Elysia, t } from "elysia";

import { db } from "../db/client";
import { posts } from "../db/schema";
import { authGuard } from "../middleware/requireAuth";

export const exampleRoutes = new Elysia({ prefix: "/api/example" }).use(authGuard).post(
  "/",
  async ({ body, userId, set }) => {
    const [created] = await db.insert(posts).values({ userId, content: body.content }).returning();

    if (!created) {
      set.status = 500;
      return { error: "Failed to create" };
    }

    set.status = 201;
    return created;
  },
  {
    body: t.Object({
      content: t.String({ minLength: 1, maxLength: 500 }),
    }),
    isAuth: true,
  },
);
```

## Conventions

- **Language:** code, comments, commits and documentation are in English. UI strings live **only** in the i18n dictionaries.
- **Commits:** Conventional Commits — allowed types include `feat`, `fix`, `docs`, `chore`, `ci`, `refactor`, `test`; imperative mood.
- **Imports:** type-only imports **must** use `import type` (`verbatimModuleSyntax`); keep the configured import order (perfectionist / `eslint-plugin-import`).
- **Server code:** strict TypeScript with `noUncheckedIndexedAccess` (handle `undefined` from indexed access); **no** non-null assertions.
- **Client code:** `<script setup>` with the Composition API; shared logic goes into composables; `noUnusedLocals` and `noUnusedParameters` are enabled — no dead code.
- **Error handling:** the server returns `{ error: "..." }` with proper statuses; the client catches `Error` instances and shows `error.message` with an i18n fallback.
- **Formatting:** Prettier owns formatting (including Markdown tables); `eslint --max-warnings 0`, no warnings allowed.

## Git and PR workflow

1. Start from `develop`: `git checkout develop && git pull && git checkout -b feature/name`.
2. Branch prefixes (validated by the `pre-push` hook): `feat/*`, `feature/*`, `fix/*`, `hotfix/*`, `chore/*`, `refactor/*`, `test/*`, `docs/*`, `ci/*`, kebab-case.
3. Commit (the `pre-commit` hook runs Prettier + ESLint + full typecheck; `commit-msg` runs commitlint).
4. `git push -u origin feature/name`.
5. Open a pull request into `develop` and merge it with **Create a merge commit** (squash is not used); delete the branch.
6. Locally: `git checkout develop && git pull && git branch -d feature/name && git fetch --prune`.
7. Releases: update `CHANGELOG.md` (Keep a Changelog format), open a PR `develop` → `main` titled `Release vX.Y.Z`, merge it, then `git tag -a vX.Y.Z -m "..."`, `git push origin --tags`, and return to `develop`.

**Never push directly to `main`/`develop` and never force-push them.**

## Internationalization rules

- **Every user-visible string must come from `t("key")` — never hardcode UI text.**
- New keys go into **both** `client/src/i18n/en.json` and `ru.json` — the key sets **must stay identical**.
- Key namespaces: `nav.*` (header), `auth.*` (register/login forms), `feed.*` (feed page, plural counter `feed.posts`), `post.*` (post card).
- Default locale is `en`; the selected locale is persisted in `localStorage["locale"]`; `fallbackLocale` is `en`.
- Plural forms are pipe-separated (`"no posts | {count} post | {count} posts"`); the Russian rule lives in `client/src/i18n/index.ts` (`pluralRules` — the Composition API option name; `pluralizationRules` is silently ignored).
- Dates: `d(value, "long")` (Today/Yesterday labels are separate translations `feed.today` / `feed.yesterday`); time: `d(value, "time")` with `datetimeFormats` — English renders 12-hour time, Russian 24-hour.
- **`@` is a special character in vue-i18n messages** — escape it (`you{'@'}example.com`) or keep the string out of the dictionaries.
- Switching the locale updates every component automatically (vue-i18n reactivity); there is nothing extra to reload.

## Known gotchas

| Situation                                                            | Explanation                                                                                                       |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `git status` shows many modified files, `git diff` is empty          | Windows CRLF artifact (autocrlf); nothing is actually changed — do not "fix" the files                            |
| Two lockfiles                                                        | Root `bun.lock` and `client/bun.lock`; each goes with its own `package.json`                                      |
| Russian plural forms are wrong (`5 поста`)                           | The rule must be passed as `pluralRules` (Composition API); `pluralizationRules` is silently ignored              |
| The page crashes with `Invalid linked format`                        | A message contains the special `@` character — escape it (`{'@'}`) or move the string out of the dictionary       |
| Changed `POSTGRES_*` in `.env`, but the database is unchanged        | PostgreSQL applies them only on the first volume init; recreate with `docker compose down -v` (data loss)         |
| `EADDRINUSE` on 3000/5173                                            | Port taken by another process (often a second instance): find it with `netstat -ano \| findstr :3000` and kill it |
| `vue-tsc` fails on unused variables                                  | The client tsconfig enables `noUnusedLocals` and `noUnusedParameters` — remove the code or use it                 |
| TypeScript complains about `arr[0]` possibly being `undefined`       | `noUncheckedIndexedAccess` is on in the server tsconfig — guard the value with a check before using it            |
| A translation key is missing                                         | vue-i18n falls back to English, then shows the key itself — the app never crashes, but add the missing key        |
| Commands fail with `DATABASE_URL is not set in .env`                 | Bun reads `.env` from the working directory — run commands from the repository root; drizzle-kit needs it too     |
| Just registered, but there is no token                               | Registration does not log you in — the UI redirects to `/login`; use the `login` endpoint for a token             |
| A `401` does not log the user out                                    | There is no auto-logout in the client — pages display the error; call `logout()` if the session is broken         |
| `me` returns `404` for a valid token                                 | The user was deleted; treat it as a logged-out state and clear the session                                        |
| TypeScript version is pinned to `~6.0.2` (both `package.json` files) | TypeScript 7 breaks `typescript-eslint`; do not bump it, even though newer versions exist                         |

## Manual end-to-end walkthrough (no automated tests — this replaces them)

1. Open `http://localhost:5173` → redirected to `/feed`; anonymous users see only the login hint and the feed.
2. Register a new account → success message → automatic redirect to `/login` after 1.2 s.
3. Log in → header shows the username, the post form appears with the `0 / 500` counter.
4. Publish a post → it appears at the top under the `Today` divider; the counter switches to a plural form (`1 post`).
5. Switch to RU → all labels change; the date becomes `Сегодня`, the time switches from 12-hour to 24-hour; reload → the locale persists.
6. Log out → the token is cleared, the form disappears, the login hint returns.
7. Try to break it: wrong password → `Invalid email or password`; duplicate registration → `email is already taken` / `username is already taken`; empty post is not submittable (button disabled).

## Glossary

- **API** — the Elysia server in `server/` (HTTP/JSON, port 3000).
- **SPA** — the Vue client in `client/` (single page, client-side routing, port 5173).
- **Bearer token** — a JWT sent in the `Authorization: Bearer <token>` header.
- **Guard / `isAuth`** — the Elysia macro that protects a route and provides `userId` to the handler.
- **Macro** — Elysia's mechanism for reusable per-route behavior (used for auth in this project).
- **Dictionary** — a locale JSON file in `client/src/i18n/` (`en.json`, `ru.json`).
- **Drizzle type helpers** — `User`, `NewUser`, `Post`, `NewPost` derived from the schema tables.
- **Feed** — the public list of the latest 50 posts (`GET /api/posts`).

## Never do

- **Never commit `.env` or any secrets** (`JWT_SECRET`, real credentials).
- **Never push directly to `main` or `develop`** and **never force-push them** — only through pull requests.
- **Never edit a migration that has already been applied** — change `schema.ts` and generate a new migration.
- **Never render user data as raw HTML** (`v-html`) — that opens an XSS hole.
- **Never rename or restructure API routes** without updating `docs/API.md` and the README.
- **Never commit** `node_modules`, `dist`, `client/dist`.
- **Never bypass git hooks** with `--no-verify`.

## CI

`.github/workflows/ci.yml` runs on pushes to `main`/`develop` and on pull requests targeting them: install (server + client, `--frozen-lockfile`) → `ci:format` → `lint` → `typecheck` → client `build`. A red CI blocks merging. **When dependencies change, commit the lockfile(s)** (`bun.lock` and/or `client/bun.lock`) **together with `package.json`** — otherwise the frozen install fails.

## Critical rules (repeat)

The most important rules, repeated one more time:

1. **Never commit secrets** — `.env`, `JWT_SECRET`, credentials.
2. **Never push to or force-push `main`/`develop`** — always open a pull request.
3. **Never edit applied migrations** — update `schema.ts`, then `bunx drizzle-kit generate`.
4. **Never use `v-html`** with user data.
5. **Every user-visible string goes through `t()`**; new keys go into **both** `en.json` and `ru.json`.
6. **Dependencies changed → commit the lockfile(s)** together with `package.json`.
7. **Before finishing, all checks must be green:** `bun run lint`, `bun run typecheck`, `bun run ci:format`, and `cd client && bun run build` for client changes.
8. **Commit messages follow Conventional Commits** — the hook will reject anything else.
9. **Do not bypass hooks** — fix the cause instead of using `--no-verify`.
10. **If the API port changes, update both** `listen(3000)` and the client `API_URL`.
